# v2.1.0–v2.1.9 Post-GA Operations Evidence Train

Date: 2026-08-22

## Decision and safety boundary

`v2.0.x` ended with a separately signed closure archive. This next bounded train
does not reinterpret that archive as a local authorization, release, or claim
that a managed production system exists. It accepts only externally generated,
detached-signature attestations and always reports `externalStatus: hold` and
`productionStatus: blocked`.

The Studio has no endpoint that can create these records, sign them, call an
operator, change SLOs, settle billing, delete data, execute a failover, or
transition a production deployment.

## Attestation intake contract

For each control key, configuration is deliberately external to the repository:

`FIRST_LLM_POST_GA_<CONTROL>_PATH`,
`FIRST_LLM_POST_GA_<CONTROL>_SIGNATURE_PATH`,
`FIRST_LLM_POST_GA_<CONTROL>_PUBLIC_KEY_PATH`, and
`FIRST_LLM_POST_GA_<CONTROL>_KEY_SHA256`.

Controls are `CONTINUITY`, `SLO`, `CHANGE_INCIDENT`, `DATA_GOVERNANCE`,
`IDENTITY_ACCESS`, `SUPPLY_CHAIN`, `QUALITY_SAFETY`, `CAPACITY_COST`,
`RECOVERY`, and `INDEPENDENT_REVIEW`.

Each configured record must be JSON signed with `RSA-SHA256`; the detached
signature and public key are read only. The code verifies the pinned public-key
SHA-256, record SHA-256, exact schema, durable issuer/record identity, nonfuture
generation time, unexpired expiry time, and required semantic control fields.
Every record after `v2.1.0` must bind the immediately previous verified record
by version, digest, and record id. The final review must bind all nine predecessor
digests in order and its issuer must differ from every predecessor issuer.
