# v3.6.0-v3.7.4 Owner Receipt and Exception Lifecycle Plan

Date: 2026-08-30

## Decision

The v3.4-v3.5 train already produced strict owner workload requests and an
instant candidate receipt validator. The next 15 versions close the missing
repository-owned execution boundary: authenticated candidate intake, durable
digest-only retention, quarantine, compensation reconciliation, escalation
acknowledgement, bounded waiver expiry, and deterministic decision packages.

This train does not verify detached external signatures, write to an immutable
organization archive, approve distribution, or authorize production.

## Implemented boundary

- `features/experiments/owner-receipt-lifecycle.ts` owns the durable local
  ledger and event reducer.
- `features/experiments/owner-receipt-lifecycle-application.ts` owns mutation
  dispatch and read-model refresh.
- `GET /api/experiments/owner-receipt-lifecycle` exposes the v3.6 train.
- `POST /api/experiments/owner-receipt-lifecycle` supports
  `intake-receipt` and `reconcile-compensation` after operator authorization.
- `GET /api/experiments/operational-exception-lifecycle` exposes the v3.7
  train.
- `POST /api/experiments/operational-exception-lifecycle` supports
  `acknowledge-escalation`, `request-waiver`, and `expire-waiver` after
  operator authorization.

Every mutation requires `expectedRevision`. A stale writer receives a conflict
instead of overwriting the ledger. Each event binds the preceding event digest.
Receipt payloads are reduced to SHA-256 metadata and validation blockers; raw
receipt content is not persisted. Protected waiver scopes are rejected, and
all local states retain `productionStatus: blocked`.

The seven attention signals are the seven owner-specific receipt intake
milestones. A missing candidate is reported as missing; it is not replaced by
a fixture. Ledger integrity, compensation policy with no unresolved quarantine,
SLA detection, acknowledgement mechanics, waiver policy, and decision package
assembly are source-complete.

## Acceptance

1. Strict valid receipts append a candidate event but remain externally unsigned.
2. Invalid or unexpected fields append a quarantine event without persisting the raw payload.
3. Stale revisions fail with a conflict.
4. Compensation binds an exact receipt event and strict evidence digest.
5. Protected waiver scopes and durations above 24 hours fail closed.
6. Expiry and acknowledgement append events without rewriting earlier state.
7. UI, API smoke, evidence export, release train, and route ownership use the same contracts.
8. Source validation cannot change distribution or production authority.

## External completion path

Authorized owners must execute the seven real workloads, submit current
digest-bound receipts, verify detached signatures against pinned organization
trust anchors, retain exact bytes in immutable storage, reconcile incident and
waiver events with external systems, and obtain distinct receipt and operating
authority closures. Until then the source train may be complete while the
release remains `HOLD` / `BLOCKED`.
