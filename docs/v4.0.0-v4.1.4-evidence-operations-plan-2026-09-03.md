# v4.0.0-v4.1.4 Evidence Operations Plan

Date: 2026-09-03

## Objective

The previous competitive-product train made fifteen product contracts explicit.
This train turns the remaining real-workload gaps into strict, durable evidence
operations. It does not promote a fixture, local rehearsal, or unsigned
candidate into external assurance, distribution approval, or production
authority.

## Shared Receipt Contract

`evidence.operational-candidate.v1` is the only candidate input accepted by the
train. Validation is fail-closed and requires:

- exact known fields and the expected milestone;
- a non-placeholder subject plus durable organization and operator identities;
- SHA-256 workload and artifact digests;
- a passing outcome and every milestone-specific non-negative metric;
- ordered execution timestamps within 24 hours and evidence no older than seven days;
- an optional valid predecessor digest.

Accepted candidates are stored atomically with a derived evidence digest. A
candidate may close only its local operation. `externalSignaturePending` and
`productionTransitionDenied` remain true by contract.

## Product and API Surface

- `/experiments` renders the train beside the prior competitive-product train.
- `GET /api/experiments/evidence-operations-train` returns the current read model.
- Operator-authenticated `POST` accepts one strict candidate receipt or records
  the aggregate train state.
- `npm run evidence:v400-v414-evidence-operations` exports a machine-readable
  aggregate receipt without inventing missing workload evidence.

## Promotion Rules

1. Source completion means all fifteen contracts, read models, UI, API, tests,
   and documentation exist.
2. Local completion requires a current passing signal or a valid observed
   candidate for each of the first fourteen milestones.
3. `v4.1.4` passes only after all fourteen domain milestones pass. A receipt for
   the aggregate gate cannot bypass missing domain evidence.
4. External assurance requires independently controlled signatures, trust
   roots, immutable archive read-back, and owner review.
5. Distribution remains `HOLD` and production remains `BLOCKED` until those
   external authorities approve the exact candidate.
