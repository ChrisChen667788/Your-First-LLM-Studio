# v2.8.0-v2.9.4 Operational Remediation and Sustainability Plan

Date: 2026-08-30

## Decision

The next 15 source versions convert measurable gaps in the existing feature-owned
read models into a prioritized remediation and sustainable-operations train.
They do not create production authority and they do not replace external workload,
identity, infrastructure, billing, support, Apple release, or assurance evidence.

- `v2.8.0-v2.8.9` covers provider, Retrieval, model supply chain, workspace audit,
  runtime, Agent, Workflow, Benchmark, Fine-tune, and independent remediation.
- `v2.9.0-v2.9.4` covers telemetry, incident diagnostics, Admin compatibility
  sunset, desktop upgrade/data lifecycle, and independent closure.
- Source implementation is complete when the read models, API projections, UI,
  tests, route smoke, export, ownership, and docs agree.
- Local readiness may remain `attention`; signed external evidence remains `HOLD`;
  production remains `BLOCKED` until every independent record verifies.

## Ownership

- `operational-sustainability-source-signals.ts` is an exception-safe, read-only
  projection over the owning Provider, Retrieval, Models, Governance, Agent,
  Workflow, Benchmark, Fine-tune, Telemetry, Admin, and Desktop modules.
- `operational-remediation-efficiency-train.ts` and
  `sustainable-operations-upgrade-train.ts` own version definitions, external
  record keys, predecessor chains, and fail-closed transitions.
- The API routes are thin read-only transport wrappers.
- `OperationalSustainabilityPanel.tsx` renders local signals beside signed
  external status; it does not mutate owner state or authorize production.
