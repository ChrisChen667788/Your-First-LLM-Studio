# v4.4.0-v4.5.4 Evidence Adjudication and Retention Plan

Date: 2026-09-07

## Objective

The previous collection train can safely queue, collect, review, and export
candidate receipts. This train adds the repository-owned decision boundary
around those receipts: reviewer attestations, artifact read-back metadata,
metric policies, independent re-observation contracts, portable export, and
revocation-aware aggregation.

It does not claim that a local identifier is an organization principal, that a
local file is immutable object storage, or that a test port is a live external
authority. External identity verification, archive read-back, independent
observation, distribution, and production authority remain fail-closed.

## Source and Evidence Boundaries

- All fifteen repository contracts are source-complete and exposed by
  `/api/experiments/evidence-adjudication-train` and `/experiments`.
- Deterministic local controls validate strict reviewer attestations, artifact
  manifest shape, retention metadata, metric coverage, threshold integrity,
  portable export shape, and revocation behavior. They do not create accepted
  workload packages.
- `verifyEvidenceAdjudicationPackage` accepts an injected external port only
  after the local binding checks pass. The default port is deliberately
  unconfigured and returns a policy error; no HTTP request or fixture can turn
  that into external evidence.
- A valid source/test port proves adapter behavior only. A real IdP or trusted
  organization key verifier and Object Lock-equivalent read-back are required
  before a live package can be authoritative.
- This train cannot change `distribution: HOLD` or `production: BLOCKED`.

## External Acceptance Inputs

1. Pinned organization issuer, reviewer subject, organization mapping, and
   signing-key verification receipt.
2. Immutable archive object read-back bound to the accepted receipt digest,
   retention policy, and read time.
3. A distinct-worker or distinct-organization re-observation that binds the
   same workload, artifact, and metric-policy digests.
4. Qualified domain-owner threshold/baseline approval and independent final
   acceptance decision.

## Verification Contract

- Unit tests cover catalog exactness, strict malformed/stale rejection, metric
  policy tamper denial, default external-port fail-closed behavior, and a
  dependency-injected verified port.
- The API route appears in CI and cross-surface smoke. The panel reports
  source, local, accepted-package coverage, external, and production state.
- The evidence script calls the live API, writes a digest-bound local snapshot,
  and retains `HOLD` / `BLOCKED` state unless independent receipts are present.
