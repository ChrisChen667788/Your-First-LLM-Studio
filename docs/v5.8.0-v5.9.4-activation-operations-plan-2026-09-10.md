Date: 2026-09-10

## Ownership and Boundaries

`features/evidence/activation-operations/` owns policy validation, trust
snapshot derivation, operational projection, case ownership, rotation/decision
admission, audit export and merge. The activation intake ledger remains the
source of signed records and is reverified before every operational projection.
`/api/experiments/activation-operations` is a thin transport adapter. The CLI
and Experiments panel use the same application service.

No operation accepts a private key or caller-supplied trust root. The policy
file and trust file are regular, non-symlink, bounded, non-group-writable files
outside the repository. Rotations reference public-key fingerprints; the actual
key material remains operator-managed. Export contains no public PEM or private
key, and merge cannot delete newer operation state.

## Readiness Contract

`eligibleForReview` requires a current valid policy bound to the current trust
snapshot, a current manifest, no admitted rotation that invalidates the
manifest, no conflicting evidence digest, no open quarantine, all six global
stages, and matching evidence from distinct observer/verifier issuers across
all fourteen source milestones. A decision admission is a consumed record for
the exact request. None of these states can authorize deployment, distribution,
or production.

The default machine has no organization policy or trust path configured. Local
generated keys and fixtures are test evidence only. External authority,
immutable archive, independent operators, distribution and production remain
outside repository authority. See the [operator guide](./activation-operations-operator-guide.md)
and [validation record](./release-evidence/v5.8.0-v5.9.4-activation-operations-2026-09-10.md).
