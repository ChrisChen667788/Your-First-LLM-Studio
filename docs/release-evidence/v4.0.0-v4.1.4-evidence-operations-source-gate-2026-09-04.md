## Security Repair Evidence

The initial preflight correctly failed closed when its synchronous child audit
timed out. A direct registry audit then identified `fast-uri 3.1.5` and
`qs 6.15.3` advisories. The lockfile now resolves `fast-uri 3.1.6` and
`qs 6.16.0`; `npm audit --omit=dev --json` reports zero production
vulnerabilities. The preflight audit runner now uses an asynchronous child with
a project-aligned Node 22/npm runtime, a 180-second overall timeout, bounded
registry retries, and 20 MiB output bounds, preventing the prior false
unavailable result while preserving fail-closed behavior.

The complete passing preflight is archived locally as
`output/release-security/history/security-preflight-2026-09-04T08-19-14-649Z.json`:
it scanned 1,314 candidate files, found no secret findings, reached the registry,
and reported zero production vulnerabilities. A later rerun at
`2026-09-04T09:02:18.022Z` scanned the current 1,316-file candidate set with no
secret findings and verified repository integrity, but correctly returned
`blocked` because the registry audit exceeded 180 seconds. That network failure
does not replace the archived audit result and is not represented as a current
