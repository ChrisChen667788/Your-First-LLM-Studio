# v1.4.0 Workspace Governance Foundation Evidence

Date: 2026-07-23

Status: local organization/group mapping and concurrent-user conflict evidence `PASS`; enterprise production promotion `HOLD`.

## Implemented Boundary

- Workspace identity arrives through a short-lived HMAC-signed context when a trusted identity proxy is configured. Unsigned remote and forwarded requests fail closed.
- Loopback-only single-user mode resolves only the configured local organization, workspace, and operator.
- SQLite resource reads and writes bind organization, workspace, subject membership, and role permission in SQL.
- Workspace audit events are append-only. Database triggers reject update and delete attempts.
- Postgres request context is transaction-local, RLS is forced on workspace resources, the `execute` action follows the builder/admin/owner policy, and audit events use a security-definer append function plus immutable triggers.
- `/api/governance/workspaces/resources` is the thin application boundary for scoped list/create/update operations, optimistic revision checks, and optional admin audit reads.
- SCIM groups bind explicitly to one organization/workspace/role. OIDC resolution requires both a matching `sub` and group claim; inactive users, missing claims, and cross-organization mappings fail closed.
- Workspace resources carry a monotonic revision. A stale second writer receives the typed `workspace_resource_revision_conflict` response with HTTP 409, and both winning and rejected writes remain auditable.
- Admin renders the feature-owned `WorkspaceGovernancePanel`; governance state and actions do not return to `AdminDashboard`.
