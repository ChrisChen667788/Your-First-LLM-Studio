## Implemented source

- Candidate receipts use strict action, request, digest, identity, time-window,
  rollback, and evidence validation before entering the lifecycle ledger.
- Invalid candidates are quarantined by digest; sensitive source payloads are
  not persisted in quarantine records.
- Receipt events are append-only and revisioned. Stale writers fail with an
  optimistic concurrency conflict instead of overwriting a newer event.
- Compensation events bind to the quarantined event without rewriting history.
- Operational exceptions expose SLA breach, acknowledgement, protected-scope
  waiver policy, bounded expiry, and deterministic decision packages.
- Local receipts remain candidates. Detached signatures, pinned trust anchors,
  external archives, independent authorities, and production transitions stay
  fail-closed.
- The competitive review adds `v3.8.0-v3.9.4` as 15 `planned` milestones; none
  of those future slices are represented as implemented by this gate.
