## v1.10.2 implementation update

`Runtime Recovery and Performance Evidence` now has its own fail-closed,
durable contract at `/api/models/runtime-recovery-performance` and a Model Hub
panel. It records no prompt text. A performance receipt instead contains model,
runtime, profile, host-hardware, and prompt digests plus TTFT, tokens/s, memory,
queue wait, repeated-context state, raw metric values, and a receipt digest.
Only two complete local receipts with the identical comparison key can become
comparable.

The same ledger persists safe-boundary checkpoints for local prewarm/load,
unload, gateway restart, model-acquisition cancellation/resume, and benchmark
run execution. A restart is completed only after its safe boundary is written,
the runtime is reachable, and a resumed transition is recorded. The feature is
wired into the relevant runtime and benchmark paths; its local status remains
`HOLD` until complete same-profile receipts and all required operation records
exist. External and production state remain `HOLD`.

## v1.10.3 implementation update

`Workspace Provenance and Operator Context` now has a request-bound read model
at `/api/governance/workspace-provenance` and a compact foreground chip in the
Agent workbench. It resolves and displays the current subject, workspace,
organization, request, execution locality, and data boundary for the active
request. The durable receipt path stores only SHA-256 digests of those
identifiers, plus the signed/loopback mode and context freshness; it never
stores the identifiers themselves.

The context resolver retains loopback fallback, invalid-signature, stale-context,
and cross-workspace denial behavior. Agent session snapshots are explicitly
disclosed as local and not yet workspace-scoped, rather than being represented
as tenant-isolated persistence. OIDC/JWKS, SCIM lifecycle, non-loopback traffic,
and organization review remain external and production `HOLD` gates.

## v1.10.4 implementation update

`Agent Action Trust and Recovery` now combines protected-action interruption,
duplicate-side-effect accounting, replay-fork omission, and breakpoint state-diff
evidence at `/api/agent/action-trust-recovery`. The Agent foreground shows the
four checks together and can run the existing LangGraph protected-action shadow
through the operator-controlled endpoint. A local pass requires all four
receipts; executing the shadow alone does not fabricate replay or state-diff
proof. Multi-client reconnect, real protected-tool execution, approval UX, and
billing/quota reconciliation remain external and production `HOLD` gates.

## v1.10.5 implementation update

`Workflow Debugger Closure` now exposes a node-oriented debugger read model at
`/api/workflows/debugger-closure` and embeds it in the Workflow Studio. Every
selected execution is bound to its graph id, version, digest, current node,
redacted input/output/error cards, and recent event locator. Raw execution
payload is not retained in the debugger receipt or rendered by the card; each
captured value is represented by a digest, length, and secret classification.

The operator-only local rehearsal creates a failed execution with a deliberately
secret-shaped value, forks a replay, and records the breakpoint state diff. A
local pass therefore requires the failed node, immutable graph digest, redacted
failure card, side-effect-free replay receipt, and matching breakpoint state
diff. Resume, continue, and fork actions remain under the existing operator
boundary. Distributed checkpointing, production traces, browser acceptance, and
operator recovery review remain external and production `HOLD` gates.

## v1.11.0 implementation update

`Artifact Federation Trust` now combines the registry-adapter policy, publisher
trust roots and revocation, provenance, local immutable registry read-back,
signed staging read-back, and trusted atomic installation at
`/api/artifacts/federation-trust`. The Experiments foreground presents all ten
checks and can execute an operator-only local rehearsal.

That rehearsal creates a unique local package, active and retired Ed25519 keys,
a passing local provenance/registry/install/read-back chain, and two rejection
cases: a revoked signer and a digest-mismatched read-back. It neither contacts
nor mutates GitHub, ModelScope, Hugging Face, OCI, or any other remote registry.
The imported read-back shape is therefore local evidence only, not a claim of
provider-side publication. Independent publishers, controlled registry
credentials, provider-side read-back, quarantine review, revocation propagation,
and organization approval remain external and production `HOLD` gates.

## v1.11.1 implementation update

`Model Supply Chain Operations` now has a unified read model at
`/api/models/supply-chain-operations` and a Models Studio panel. It joins an
authenticated immutable multi-file Hub receipt and reconciliation with local
source-manifest, transfer scheduling/backoff, content deduplication, isolated
placement migration, compatibility preflight, shared-blob quarantine/removal,
and drain-aware activation rollback evidence.

The operator-only rehearsal exercises the local mechanics only. It does not
create a Hub session, download a model, invoke a converter, or touch an external
volume; consequently it cannot satisfy the immutable authenticated Hub checks.
An isolated rehearsal therefore correctly returns `localStatus: HOLD` until a
real authenticated multi-file Hub receipt and non-empty reconciliation receipt
exist. Authenticated multi-Hub traffic, real converter execution, external-volume
reconnect repair, mirror recovery, live-store garbage collection, license/malware
review, and organization approval remain external and production `HOLD` gates.

## v1.11.2 implementation update

`Continuous RAG Governance` now has a unified read model at
`/api/retrieval/governance` and a Retrieval Studio panel. Its operator-only local
rehearsal writes a uniquely identified temporary document, revises it, runs a
golden query and its replay diagnostic, deletes the document, and confirms that
the deleted document is no longer returned by the local index. The durable
receipt retains only the document id, a revision digest, replay ids, and boolean
outcomes; it does not retain temporary source text or a principal's raw identity
context.

The rehearsal also runs a pure, RLS-shaped access-policy probe for cross-workspace
denial, unauthorized-subject denial, and authorized-subject allowance. This
models the intended policy boundary but does not execute PostgreSQL RLS. An
isolated rehearsal proves the local corpus lifecycle, citation-diagnostic,
deletion, and policy mechanics, but correctly returns `localStatus: HOLD` until
the enterprise pgvector, embedding, reranker, and RLS dependencies are configured.
Managed connector ingestion, deployed index/cache/citation deletion propagation,
real identity leakage probes, freshness/deletion SLO measurement, and all
production results remain `HOLD` gates.

## v1.11.3 implementation update

`Reproducible Training Recipes` now has a unified read model at
`/api/finetune/reproducible-recipes` and a Fine-tune Studio panel. Its
operator-only rehearsal canonicalizes a supported MLX LoRA plan, checks that the
canonical JSON round-trips, binds digest-only base-model, dataset, runtime, and
evaluator pins, and verifies that a preview backend cannot be treated as an
executable worker plan. The rehearsal records only the recipe digest, input
digests, and boolean checks; it neither starts a worker nor writes a package.

Local `PASS` additionally requires a passing pre-existing Fine-tune quality/export
receipt with locally verified package read-back and rollback. The isolated
rehearsal therefore correctly returns `localStatus: HOLD` when no such package
receipt is present. Independent worker replay, representative quality/cost
measurement, model-card review, authenticated remote registry publication and
read-back, and release approval remain production `HOLD` gates.

## v1.11.4 implementation update

`Quality Policy and Safety Review` now has a unified read model at
`/api/evaluation/quality-policy-safety` and an Experiments panel. Its
operator-only rehearsal binds a versioned controlled-release policy digest and
checks aggregate non-inferiority, safety, latency, cost, calibration, and
disagreement thresholds. It also proves that an expired or self-approved waiver
fails closed, and that a rollback-playbook digest plus aggregate local red-team
fixture are required. It neither submits prompts to a model nor represents the
fixture as an organization safety review.

Local `PASS` additionally requires passing Quality CI, artifact-to-quality, and
regression-suite receipts. The isolated rehearsal correctly returns
`localStatus: HOLD` where those real evidence receipts are absent. Repository
enforcement, approved human labels, live red-team execution, accountable waiver
review, release authority, and independent rollback acceptance remain production
`HOLD` gates.

## v1.12.0 implementation update

`Enterprise Control Plane Candidate` now has a unified read model at
`/api/deployment/enterprise-control-plane` and an Experiments panel. Its
operator-only rehearsal creates a local deployment-control-plane receipt and
joins the current deployment revision with opaque usage, audit, local-signing,
failover, local identity lifecycle, settlement-retry, and redacted-retention
references. It also records a scoped-policy contract requiring a policy diff,
distinct approver, and rollback reference. The candidate receipt contains no
token payload, caller secret, identity body, or request-log body.

The local rehearsal can verify local usage accounting, retry/idempotency, hashed
audit archival, local signing, failover RPO/RTO counters, local identity
lifecycle, and local request-log redaction/retention. A fresh integrity-verified
release-security report is still required for local `PASS`. Neither a local
archive nor a local signing key is cloud Object Lock/KMS evidence, and neither a
local approval boundary nor a local failover is organization approval or
multi-region acceptance. Managed PostgreSQL, real OIDC/SCIM, cloud KMS/Object
Lock, billing acknowledgements, multi-region failover, independent security
testing, and organization sign-off remain production `HOLD` gates.

## Non-promotion disclosure

Every version has `externalStatus: HOLD` and `productionStatus: HOLD`. The source
train is not evidence of managed identity/data/telemetry/billing, remote registry
operation, Apple signing/notarization, independent security/HA testing, or
organization approval. A `POST` receipt is an operator-authenticated snapshot of
the local source/read-model state, not a release promotion.
