## Enterprise IdP / SCIM

- OIDC discovery validates the configured issuer and required authorization, token, and JWKS endpoints.
- JWKS probing requires at least one usable signing key and never persists provider bearer tokens.
- The outbound SCIM adapter validates `ServiceProviderConfig`, paginates standard `ListResponse` resources, and atomically replaces the local directory only on an explicit sync action.
- A loopback standards-conformance IdP/SCIM server passed discovery, JWKS, user, group, and local-directory synchronization checks.
- No organization IdP tenant or independent operator receipt was available, so production remains `HOLD`.

The protocol shape follows [OpenID Connect Discovery](https://openid.net/specs/openid-connect-discovery-1_0.html) and [SCIM RFC 7644](https://datatracker.ietf.org/doc/rfc7644).

## Durable Lease / Worker Failover

- PostgreSQL 16 stores the lease owner, database-clock expiry, heartbeat, monotonic fence token, recovery count, release marker, and revision.
- Lease claims use one transaction, an execution-scoped advisory lock, and a row lock; heartbeat and release require the current owner and fence token.
- Two separate Node worker processes ran against a Docker PostgreSQL instance. Worker A exited without release; Worker B was rejected while the lease was live, reclaimed it after expiry, advanced fence `1 -> 2`, heartbeated, and released it.
- Local checks: `7/7 PASS`.
- Frontend evidence-store receipt: `remote-worker-failover-0489c58d-2b5a-4795-af46-be6eb5115f50`.

This is process-isolated, single-host evidence. It does not satisfy cross-host network-partition, database failover, or protected-side-effect duplicate-denial gates.
