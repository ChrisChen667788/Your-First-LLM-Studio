# v3.0.0-v3.1.4 Remediation Control and Service Readiness Plan

Date: 2026-08-30

## Decision

The next 15 source versions convert the unresolved v2.8-v2.9 owner signals
into an accountable remediation control plane, then project customer-facing
service readiness without weakening external evidence or production authority.

- `v3.0.0-v3.0.6` gives each current attention signal an owner, priority,
  dependencies, acceptance checks, next actions, and evidence fingerprint.
- `v3.0.7-v3.0.9` adds an acyclic dependency graph, deterministic evidence
  package, and independent remediation acceptance.
- `v3.1.0-v3.1.4` covers service-readiness disclosure, support diagnostics,
  upgrade/change readiness, operational transition, and independent closure.
- Source completion means the contracts, read models, APIs, UI, tests, export,
  ownership, and documentation agree. It does not mean every remediation ran.

## Control-plane Contract

`operational-remediation-control-plane.ts` reads the 15 v2.8-v2.9 owner
signals and emits:

- exactly one policy and evidence fingerprint per signal;
- `critical | high | medium | low` priority and accountable owner;
- acyclic dependencies and deterministic topological order;
- `satisfied | open | blocked | external-only` state;
- explicit acceptance checks, next actions, review window, evidence route, and
  blocker propagation;
- a deterministic state digest with local production transition denied.

Current read: `2 satisfied`, `3 open`, `8 blocked`, and `2 external-only`.
Five unresolved items are critical priority.

## API and Export Contracts

- `GET /api/experiments/remediation-control`
- `GET /api/experiments/service-readiness`
- `npm run evidence:v300-v314-remediation-readiness`
- Output: `output/release-evidence/v3.0.0-v3.1.4-remediation-service-readiness.json`

Each API is a thin read-only wrapper. Neither endpoint runs remote workloads,
changes owner state, signs evidence, or authorizes production.
