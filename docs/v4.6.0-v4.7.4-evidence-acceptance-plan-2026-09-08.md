# v4.6.0-v4.7.4 Evidence Acceptance Lifecycle Plan

Date: 2026-09-08

## Objective

`v4.4-v4.5` defines what a valid adjudication package must contain. This train
defines how that package is received, held, externally challenged, revoked,
ported, and handed to a distribution decision without confusing repository
state with an organization authority.

The repository implements the lifecycle contracts, a durable local package
store, read models, APIs, and a source-gate export. It does not configure an
IdP, KMS, HSM, object-lock archive, independent observer, distribution approver,
or production authority.

## Version Scope

| Version | Capability | Repository acceptance |
| --- | --- | --- |
| `v4.6.0` | Authority Configuration Contract | Issuer, key, JWKS, archive endpoint, and configuration digest are strict and HTTPS-only. |
| `v4.6.1` | Issuer Pin Rotation Boundary | Package is bound to one pinned issuer/key; replacements need predecessor lineage. |
| `v4.6.2` | Archive Authority Boundary | Archive read-back must be an explicit external authority, never a local path. |
| `v4.6.3` | Acceptance Package Intake | Digest-bound, idempotent durable intake with optimistic revisions and append-only events. |
| `v4.6.4` | Adjudication Binding Preflight | Every receipt, reviewer, artifact, policy, and re-observation digest is required. |
| `v4.6.5` | Acceptance Package State Machine | Draft, submitted, verified, rejected, and revoked transitions are explicit and fenced. |
| `v4.6.6` | Independent Re-observation Intake | Distinct observer plus matching workload, artifact, and policy contracts. |
| `v4.6.7` | Domain Owner Approval Binding | Decision digest is bound without replacing source metric or policy evidence. |
| `v4.6.8` | External Verification Challenge | Authority response must echo the configured issuer and exact package/artifact digests. |
| `v4.6.9` | Immutable Read-back Challenge | Artifact verification cannot proceed without matching immutable read-back evidence. |
| `v4.7.0` | Quorum Decision Ledger | Verified decision lineage remains digest-only and deterministic. |
| `v4.7.1` | Revocation Feed Intake | Revocation is append-only and excludes the package from all later handoffs. |
| `v4.7.2` | Portable Manifest Import | Portable package manifests are bounded, digest-only, and identity-checked. |
| `v4.7.3` | Coverage and Evidence Aging | Coverage counts only current verified packages and exposes missing or stale domains. |
| `v4.7.4` | Distribution Handoff Gate | Fourteen current, verified, non-revoked packages are required before a non-authoritative handoff can be ready. |

## Source and Evidence Boundaries

- `features/evidence/acceptance-lifecycle.ts` owns strict authority, package,
  re-observation, lifecycle, external-port, revocation, export, and durable
  store reducer contracts.
- The default external port throws `external-unavailable`. It makes no network
  request and cannot turn a test response, a local ID, or a local file into
  external evidence.
- `/api/experiments/evidence-acceptance-train` and `/experiments` expose
  source/local/external/production state. The source-gate export is a local
  snapshot, not an external receipt.
- Local verified-package coverage is not promoted to external or production
  authority. Organization identity, issuer/key state, immutable archive,
  re-observation, distribution approval, and production approval remain
  independent evidence requirements.

## External Acceptance Inputs

1. Pinned organization issuer/key configuration and a current verifier result.
2. Immutable archive retention and read-back evidence for every package digest.
3. A distinct observer's workload result correlated to the package artifact and
   metric policy.
4. Qualified domain-owner and distribution-approver decisions, separate from
   the package creator, worker, and reviewer.

## Verification Contract

- Unit tests cover the exact 15-version catalog, strict authority validation,
  state transitions, re-observation separation, external-port failure and
  binding, portable export, idempotency, stale-writer denial, and the source
  read model.
- Cross-surface smoke checks the API, release train, and release-evidence
  matrix. The deterministic source gate intentionally remains `HOLD` /
  `BLOCKED` until controlled external evidence exists.
