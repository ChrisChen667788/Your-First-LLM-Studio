## Verification contract

Every record must satisfy all of the following:

1. Exact schema version and no unknown top-level, predecessor, control, or issuer fields.
2. SHA-256 body digest and detached `RSA-SHA256` signature.
3. Public-key SHA-256 pin supplied outside the record.
4. Durable record, organization, operator, and key identities.
5. Non-future generation time and unexpired expiry time.
6. Exact predecessor version, digest, and record ID binding.
7. Version-specific evidence digests, observation window, coverage, zero critical findings, and required assertions.
8. Final review binds every prior digest in order and uses a reviewer distinct from the reviewed issuers.
9. `localProductionTransitionDenied` remains true for every state.

## Configuration

For every definition key, configure four values. Example for `v2.2.0`:

```bash
FIRST_LLM_CONTINUOUS_ASSURANCE_COMPLIANCE_SCOPE_PATH=/secure/evidence/v220.json
FIRST_LLM_CONTINUOUS_ASSURANCE_COMPLIANCE_SCOPE_SIGNATURE_PATH=/secure/evidence/v220.sig
FIRST_LLM_CONTINUOUS_ASSURANCE_COMPLIANCE_SCOPE_PUBLIC_KEY_PATH=/secure/trust/v220.pem
FIRST_LLM_CONTINUOUS_ASSURANCE_COMPLIANCE_SCOPE_KEY_SHA256=<64-char sha256>
```

v2.2 uses the prefix `FIRST_LLM_CONTINUOUS_ASSURANCE_<KEY>`. v2.3 uses
`FIRST_LLM_ASSURANCE_CLOSURE_<KEY>`. Absence, malformed JSON, stale evidence,
signature failure, a wrong pin, a broken predecessor, insufficient coverage,
or a non-independent final reviewer all fail closed.
